# Décisions d’implémentation

Source : spécification du 4 septembre 2026 et ses annotations, avec audit de l’export de conversation. Les anciennes réponses et les instructions de recherche dans cet export constituent du contexte, pas des commandes à exécuter.

1. La dernière annotation prime : livrer reMoodle, reAgenda, reStencil, reInk et reCalc autonomes avant les modifications Avermate. Le worktree `avermate/` est une référence isolée, sans modifications fonctionnelles.
2. Le protocole mobile `launch.php` d’Avermate a été étudié puis remplacé dans le parcours principal par le QR officiel de connexion Moodle, selon les précisions ultérieures. Authentification dans le navigateur habituel du PC/téléphone ; aucun Chromium embarqué ni compte Avermate requis.
3. L’insertion de reStencil depuis la barre d’édition dans la page active est requise. Une bibliothèque PDF ou RMDOC seule ne satisfait pas cette exigence. Aucune écriture externe du fichier de la page ouverte : utiliser une commande native en processus, versionnée et vérifiée. Une capacité absente doit être annoncée comme telle.
4. CPE Lyon est une source prioritaire de reAgenda. Le provider scolaire Avermate reste un lot ultérieur ; pas de modifications d’Avermate dans ce premier ensemble.
5. Les fils automatiquement connectés restent optionnels. reInk est expérimental mais fait partie des cinq applications prioritaires.
6. Applications C++17 / Qt Quick autonomes, exécutables séparés. La bibliothèque `repaper` mutualise transport local et coffre de secrets sans runtime Avermate. Le Bridge initial est en C++/Qt pour utiliser le SDK natif unique disponible et valider le parcours appareil ; la recommandation Rust est reportée. Les fonctions privilégiées restent un processus distinct sans réseau ni shell arbitraire offert aux apps.
7. Les secrets SSH ne sont ni copiés dans les sources ni conservés dans les journaux de test. Les tokens fournisseurs sont chiffrés AES-256-GCM dans le coffre local ; la clé séparée est protégée par les permissions du filesystem, sans prétendre protéger contre root.
8. La précision ultérieure de l’utilisateur impose les essais PC en premier, en raison du support incomplet de 3.28 par les mods. Le banc AppLoad affiche les applications natives via QTFB ; l’éditeur actif reStencil est simulé sur PC. L’intégration Xochitl réelle reste une exigence ouverte, pas une fonctionnalité abandonnée.
9. Les dépendances de distribution et lots Avermate sont reportés après cette validation PC. La liste exacte des fonctions disponibles et restantes figure dans `implementation-status.md` ; compiler pour ARM ne constitue pas une validation sur tablette.
10. Clarification ultérieure : reInk vise les outils de l’éditeur natif Xochitl. Le canvas autonome, apprécié comme MVP de test, est un banc de validation réutilisable et non la destination produit finale. L’extension native de reInk suit la même exigence que la sidebar reStencil.
11. Le parcours Moodle démarre sur la tablette : saisie des informations, transfert simple de la demande vers PC/mobile, SSO dans le navigateur externe, retour vers reMoodle. Aucun navigateur embarqué sur la tablette et aucune copie manuelle du jeton dans le parcours normal. L’utilisateur a explicitement écarté tout compagnon.
12. Tous les champs textuels, hors calculatrice, demandent le clavier natif quand la plateforme l’expose. Le fallback PC/émulateur est partagé. Dans l’émulateur, Ctrl+V et le collage tactile doivent lire le presse-papiers Windows au geste explicite de l’utilisateur, y compris dans les champs My CPE Lyon.
13. Site public avec code temporaire à huit chiffres et QR initial. Les mécanismes de protocole navigateur non universels sont écartés du parcours principal. Avec un compte étudiant seul, le parcours retenu lit localement une capture du QR de connexion du profil Moodle (ou utilise la caméra), puis chiffre la clé temporaire pour la tablette. Celle-ci échange directement la clé auprès de Moodle. La compatibilité dépend du QR de connexion activé par l’établissement et éventuellement d’une même adresse IP publique ; aucun succès réel CPE n’est affirmé sans essai de compte.

## Appareil observé

Paper Pro (`ferrari`), AArch64, logiciel 3.28.0.169, OS 5.8.202, Qt 6.10.3. Vellum 0.3.1 présent. SDK officiel publié le plus proche : 3.28.0.172 / OS 5.8.203. Cette proximité n’est pas une preuve de compatibilité : la build et les essais appareil doivent la vérifier. Aucun changement de firmware demandé ou effectué.
